## Defects & Resolution Summary

### Defect 1 — `CHAMPION.json` validation and schema integrity
- **Root cause**: Lack of strict schema version checking, nullable `model_artifact_sha256`, unvalidated generation numbers, and unchecked lineage invariants in `CHAMPION.json`.
- **Resolution**:
  - Implemented `validate_champion_state()` verifying `schema_version == 1`, non-negative integer `generation`, valid canonical `model_id` and `lineage` without duplicates, and exact 64-character lowercase `model_artifact_sha256` matching `model.zip` on disk.
  - Implemented `normalize_legacy_champion_state()` for safe backward-compatible normalization of legitimate legacy files without data loss.

### Defect 2 — `promote` and `rollback` generation tracking & SHA updates
- **Root cause**: Promotion transitions did not track `generation` counter cleanly or verify candidate existence against lineage history.
- **Resolution**:
  - Both `promote` and `rollback` now check that candidate ID is not already inside `lineage` (except when restoring/re-evaluating current champion), increment `generation` by 1, and write exact lowercase `model_artifact_sha256` into `CHAMPION.json`.

### Defect 3 — Report verification via `latest.json`
- **Root cause**: `_load_evaluation_report` did not cross-verify model IDs or artifact SHAs against `latest.json` pointers.
- **Resolution**:
  - `_load_evaluation_report` checks that `latest.json` model ID and `model_artifact_sha256` exactly match the candidate being checked and the embedded report artifact checksum. `evaluation_report_path` raises `PromotionEvidenceError` cleanly on invalid pointers.

### Defect 4 — Exclusive immutable report creation
- **Root cause**: Immutable reports were opened with `"w"` mode, which allows silent overwrites on timestamp/hash collision.
- **Resolution**:
  - Implemented `_write_exclusive_file(path, content)` using `"xb"` mode with explicit `flush()` and `os.fsync()`, raising `PromotionEvidenceError` on collision.

### Defect 5 — Git source state verification (`get_git_source_state`)
- **Root cause**: Evaluations did not record Git commit or verify whether the working tree was clean.
- **Resolution**:
  - `evaluate_candidate` calls `get_git_source_state()`, enforces `is_clean == True` (raising `PromotionEvidenceError` listing dirty paths if dirty), and records exact 40-character `source_git_commit` and `source_tree_clean=True` in every report. `_validate_evaluation_report` verifies these fields on read.

### Defect 6 — Path traversal and Windows reserved name sanitization (`validate_model_id`)
- **Root cause**: Model IDs were not checked against path separators, hidden file conventions, or Windows reserved device names (`CON`, `NUL`, etc.).
- **Resolution**:
  - Created `validate_model_id()` in `registry.py` verifying `_SAFE_ID_REGEX` (`^[a-zA-Z0-9](?:[a-zA-Z0-9_\-\.]*[a-zA-Z0-9])?$`), rejecting path traversal (`..`, `/`, `\`), rejecting leading/trailing dots/hyphens/underscores, and blocking all Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`).

### Defect 7 — Cross-process evaluation locking (`_evaluation_lock`)
- **Root cause**: Concurrent evaluation runs on the same candidate directory could interleave writes or corrupt pointer files.
- **Resolution**:
  - Created context manager `_evaluation_lock(models_dir, candidate_id)` using `.eval.lock` with exclusive creation (`"xb"`), raising `PromotionEvidenceError` if an evaluation is already running.
