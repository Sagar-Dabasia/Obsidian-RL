## Changes summary

### Failure 1 — Non-finite evidence (Req 14)

**Root cause**: `_validate_evaluation_report` checked metric *existence* only; `isinstance(float('nan'), float)` is `True`; no `math.isfinite` check; JSON written with default `allow_nan=True`.

**Fix**:
- New `_require_finite(value, field)` validator: rejects `bool`, non-numeric types, and non-finite floats with precise field-path message.
- Applied to: cost_model values, threshold values, `metrics.candidate.net_return`, `metrics.candidate.max_drawdown`.
- `_json_dumps()` uses `allow_nan=False` throughout.
- `_json_loads_strict()` re-serialises with `allow_nan=False` after parsing to close Python's `NaN`/`Infinity` JSON extension.
- `evaluate_candidate()`: non-finite strategy metrics set `passes=False` and are serialised as JSON `null` (never as `NaN`/`Infinity`).

### Failure 2 — Report overwriteable (Req 16)

**Root cause**: Single `evaluation-v1.json` unconditionally overwritten on every evaluation; no hash, no content-addressing.

**Fix**:
- Evidence now lives under `models/<id>/evaluations/`.
- Every evaluation creates `evaluation-v1-<utc_ms>-<hash[:16]>.json` (immutable, never overwritten).
- `latest.json` written atomically *after* the immutable file and points to it with `report_filename` + `report_sha256`.
- Report hash is SHA-256 over canonical sorted JSON (excluding `report_sha256` field itself), embedded in both the file and `latest.json`.
- `_load_evaluation_report()`: loads via `latest.json`, path-traversal rejected, recomputes hash, verifies `latest.json` and report agree.
- Legacy `evaluation-v1.json` (without `evaluations/` dir) is detected and explicitly rejected with a reevaluation error.
- Old public `evaluation_report_path()` now returns the latest immutable report path via `latest.json`.
- Failed evaluations also produce immutable evidence (same flow).

### Failure 3 — Non-atomic state (Req 18)

**Root cause**: `promote()` and `rollback()` made 3 sequential `write_text` calls (`set_promotion(old)`, `set_promotion(new)`, `_write_champion_data()`); crash between any two left inconsistent state.

**Fix**:
- `promote()` and `rollback()` perform **zero** per-model metadata writes. `set_promotion()` is no longer called by either.
- All state lives in `CHAMPION.json` only; updated with a single `_write_champion_atomically()` call (tempfile + fsync + `os.replace`).
- CHAMPION.json remains the sole authority for champion status.
- `current_champion()` reads CHAMPION.json with strict JSON validation.
- `_load_champion_data()` raises `RuntimeError` on malformed JSON (no silent guessing).
- Public `set_promotion()` in `registry.py` preserved for backward-compat write but not called from promotion path.

## Remaining risks

1. **Windows-specific atomicity of `os.replace`**: On Windows, `os.replace()` is documented as atomic for NTFS when source and destination are on the same volume (both in the `evaluations/` or models dir). This holds for typical usage but is not guaranteed across drives or in edge-case network mounts.
2. **`ruff`/`mypy` not installed**: Linting/type checks could not be run. Static type correctness is unverified.
3. **Per-model `metadata["promotion"]` field now stale**: Existing code or external tools that read `metadata.json` to determine champion status will see `"candidate"` for all models. This is backward-compat-breaking for any such tool; the deprecation is documented in the module docstring.
4. **Test isolation in module-scoped fixtures**: `models_with_two_candidates` is module-scoped; state leaks between tests that share it (e.g., both promotion tests run on the same `models_dir`). This pre-existed and is not introduced here.
